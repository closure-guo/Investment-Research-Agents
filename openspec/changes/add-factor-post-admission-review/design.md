# Design: add-factor-post-admission-review

## Approach

**挂载点**：`run_factor_proposal_monthly` 尾部（深度批之后）执行复核步骤——月批已构造面板、已加载库与账本上下文，且月频节奏与「全样本后验」的统计性质匹配（样本月增 ~21 个，日频复核无信息增益纯耗算力）。复核不依赖面板（只用 `factor_ic` 落库序列与账本 p 值），月批面板构造失败时复核仍可执行——但为保持 job 语义单一（fail loud 面板缺失），复核随月批同生共死。

**判据 1（水位复核）**：入库后 IC 全样本 mean/std。IC 样本从 `factor_events` 定位该因子 `candidate→active` 事件的时刻起算（等价于 `factor_ic` 中 `created_at` 之后的首条），实现上直接取 `list_ic_series` 全序列（因子入库后才开始记 IC，序列天然就是入库后样本）。

**判据 2（全局反事实）**：账本的全局 BH 反事实已在「跨批次候选检验账本」requirement 落为只读读数——本 delta 复用同一查询函数，对该因子行（`p_value` 非空、`factor_id` 非空）计算全局家族 `p_adj`。**不新增校正实现**（单一真相源），只在月批运行期消费。

**处置**：`record_status_change(active→degraded)`，与衰减监控共用事件路径，`detail` 增加 `post_admission: {icir, global_p_adj, q, threshold}` 审计块。

## Alternatives Considered

- **把全局 BH 变成闸③强制校正（准入时执行）**：BH 分母随历史假设数单调增长，早期过闸容易、后期阈值无限收紧，最终杀死全部准入（研究越多越难入库——反向激励）；且直接违反账本 requirement 的「读数 MUST NOT 改变准入结论」边界，需推翻已归档决策。被否——入库后复核是同一统计关切在不伤害准入流的落点。
- **只做判据 1（水位复核），不用全局反事实**：账本反事实读数已实现但无消费方，批内运气型假阳性（闸③小批次家族里的幸存者）只有跨批次视角能识别。保留判据 2。
- **复核不过直接 `retired`（而非 `degraded`）**：retired 无出边（终态），首月后验即判死刑太激进——月度样本仍在积累，`degraded` 保留复核恢复通道，连续弱化自然由桶内保种/重提通道出清。选 `degraded`。

## Risks

- **首批复核面可能偏大**：12 条存量因子里部分入库仅 5 个交易日（IC 样本 < 60）会被 `skipped` 保护；首批实际可复核因子少，降级面有限。上线首月读摘要人工核对降级名单合理性（incident 026 纪律：聚合指标进入处置前先逐条归因）。
- **两判据与衰减监控同日触发**：衰减监控是日批、复核是月批，同日命中同一因子时状态机幂等（已是 degraded 不重复迁移）；事件可能各落一条（reason 不同）——审计上可接受（失效形态不同），不做去重。
- **IC 样本口径**：`factor_ic` 记录受衰减监控日批驱动（面板窗 90 日），入库早于监控上线的历史因子序列可能含缺口——ICIR 对缺口不敏感（按已有样本算），如实按现有样本判定。
