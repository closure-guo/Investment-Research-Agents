# Design: add-cross-section-translation-path

## Context（承接 umbrella `optimize-factor-supply-funnel` design.md）

- **交集杠杆**：中间表示改造两头受益——转译率（769 条横截面）+ 闸④通过率（横截面因子与全量价池 IC 低相关）。#509/#510（A1）主战场在转译段，对通过率只有间接数量效应。
- **架构级改动风险**（umbrella design §28）：直出 DSL 失去 Qlib 生态既有校验，映射回归可能漏边角。
- **决策框架**（umbrella design §23）：「直出 DSL」与「Qlib 桥」两案择一，决策留在实施时做——本 design 只立对比框架与硬门禁，不预设结论。

## 两案对比（实施期 spike 的评估维度）

| 维度 | 案 A·Qlib 映射桥 | 案 B·直出本系统 DSL |
|---|---|---|
| 改动面 | 转译层映射表 + 语义核对 | RD-Agent 产出侧（外部系统）+ 回喂契约 |
| 生态校验 | 保留（Qlib 侧既有验证继续可用） | 失去，需自建等价校验 |
| 近似转译风险 | 逐算子核对可控（`Rank(x,N)`→`ts_rank` 既有考证） | 低（直接产 DSL） |
| 对 RD-Agent 的耦合 | 不动外部系统 | 需改外部 agent 侧 prompt/模板 |
| 横截面表达力上限 | 受映射表覆盖面限制 | 受本系统算子集限制（`rank`/`zscore` 已在集） |

**分期（先桥后切）**：首期按案 A 落桥（改动面小、回归面可控），观察判效读数；若桥后仍有结构性不可达（如矩阵回归类），再评估案 B。**案 B 不在本 change 首期实施**。

## 语义核对清单（硬门禁的核对表）

- Qlib `Rank(x, N)`（滚动秩，窗口 N）↔ 本系统 `ts_rank(x, N)`——窗口语义、NaN 传播、平秩（ties）处理逐值核对；
- 截面算子 `rank` / `zscore`（本系统已有，当日全截面秩/标准化）——核对 Qlib 侧同名单参形态是否混淆（Qlib 无参 `Rank(x)` 语义核对）；
- 任何映射找不到逐值等价语义 → 该构念留 `untranslatable`，MUST NOT 近似转译。

## Risks / Trade-offs

- **闸② ICIR 墙不受本 change 影响**：转译率改善不改变入库 0 的主因（A2 §7 已预判）；本 change 的验收锚在转译段，不在入库数。
- **闸③/④拒收结构会变**：横截面因子解锁后，同族查重与风格相关性拒收的桶构成改变——判效读数按桶拆读，不合成单一指标（incident 026 纪律）。
- **供给停摆期无判效数据**：设计/评审/实施不需要收割批次；判效读数开跑前置 = provider 续费 + 重开研究开关。
