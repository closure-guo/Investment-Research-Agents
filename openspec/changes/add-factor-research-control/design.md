# Design: add-factor-research-control

## Context

研发看护（RD-Agent `fin_factor` 无界循环）运行在 WSL distro `rdagent` 内，由
`tests/scripts/spike/start-factor-research.sh` 手动拉起（setsid 看护脚本 + 采集器守护），产物经
`/mnt/d` 桥写入宿主 `data/factor_research/`，后端容器挂载 `./data` 只读透传给 `/factor-research` 页。
后端容器**无法执行 distro 命令**（主规范旧注释：「控制面另议」），因此控制面必须经既有宿主
`data/` 文件桥**反向**回传（后端写、distro 读），与快照同一条桥、方向相反。

约束：

- 交互类变更（前端 UI + 状态流转）→ 全管线 + E2E 门禁 + 人工验证；
- 单 uvicorn worker 进程内前提（既有全局约束），控制端点只做文件写 + 快照读；
- distro 侧脚本已有既定启停语义（supervisor 崩溃退避自愈 / 停止终止当前会话）——控制面 MUST
  复用同一语义，不允许出现「界面上停不干净、脚本里停得干净」的双实现漂移。

## Goals / Non-Goals

**Goals:**

- `/factor-research` 页提供研发看护启停开关，端到端（点击 → 控制文件 → distro 代理 → 进程态 →
  快照 → 页面刷新）语义闭环、如实（pending ≠ 已生效）。
- 控制通道 fail-safe：无控制文件/损坏不干预；通道无存活证据（快照缺失/损坏/陈旧）时拒绝受理。
- 启停动作单一实现（代理内），手动脚本与界面走同一条语义。

**Non-Goals:**

- 收割桥 / 翻译 / 日批任务的启停开关（本次只做研发看护）；
- 多用户并发控制审计、鉴权（与既有端点同级，无鉴权）；
- distro 开机自启（与看护同级运维前提，保持手动/未来计划任务）；
- 任意命令/脚本下发（控制面只有布尔期望态）。

## Decisions

**D1 控制通道 = 宿主 `data/` 文件桥（控制文件），非网络调用。**
后端容器与 distro 之间没有可靠网络通路（容器不能执行 distro 命令，distro 侧无监听服务），而
`data/` 桥已被快照链路实证（`/mnt/d` ↔ `./data` 挂载）。备选：① distro 侧起 HTTP 服务由后端调用——
需新增监听端口、防火墙与容器→distro 路由，攻击面与运维面都变大；② 复用 ops 调度器——调度器在
容器内，够不到 distro。均否决。

**D2 控制语义 = 期望状态调和（desired-state reconciliation），非一次性命令队列。**
开关的天然语义是「期望态」：`desired_running=true` 且看护死亡 → 代理自愈拉起；`false` 且运行中 →
停掉；一致 → 零动作（幂等）。备选：命令队列（request_id 去重，一问一答）——不自愈（看护意外死亡
后不会自动恢复）、「开关位置」含义含糊、失败重投递复杂。否决。

**D3 观测与控制合一，代理**常驻**（看护停止 ≠ 代理退出）。**
这是控制面成立的关键：若沿用旧契约「看护停止后采集器写末次快照即退出」，则停止 180 秒后快照
陈旧（控制可用性门要求新鲜快照作存活证据）→ 开关被禁用 → **无法再开启**（死锁）。因此代理
独立存活：看护停止后继续周期写 `running=false` 快照并受理控制。备选：双守护（采集器 + 独立控制
守护）——两个进程都要保活、快照与控制状态可能互相矛盾。否决。

**D4 控制可用性门 = 新鲜快照作「通道存活」证据。**
`PUT /api/factor-research/control` 在快照缺失/损坏/陈旧时返回 409 `control_unavailable`，
MUST NOT 写入控制文件——不留无人受理的请求；前端同条件禁用开关并明示理由。备选：无条件接受
（fire-and-forget）——用户会看到「切换中」永久悬挂且无解释。否决。

**D5 前端不做乐观翻转。**
开关位置反映快照**实态**；`control.pending=true`（期望 ≠ 实态）期间显示「切换中」并禁用重复
操作；位置只在下一轮快照刷新后改变。备选：点击即翻转 + 失败回滚——pending 窗口内界面说谎，
且与「如实披露」的页面基调冲突。否决。

**D6 停止二次确认。**
停止会终止进行中的研发会话（在途实验作废），与手动 stop 脚本同语义；UI 单击即停的风险高于
收益，故「停止」方向加确认弹窗（「启动」方向直接生效）。参考 cohort 开关「开启需确认」的先例，
方向相反（花钱 vs 丢在途工作）。

**D7 零命令面。**
请求体只有 `desired_running` 布尔；控制文件路径由 `FACTOR_RESEARCH_CONTROL_PATH` 在调用期解析；
代理只执行已知的看护启停流程（复用既有脚本语义）。没有任何「任意命令/参数」字段。

**D8 手动脚本改薄包装，启停动作单一来源在代理。**
`start/stop-factor-research.sh` = 确保代理守护存活 + 原子写期望态 + 立即触发一次调和 + 校验/
报告；`stop` 保留 bash 兜底硬停（代理不可用时的降级路径，逐字保留旧脚本的 kill 序列）。代理以
`flock` 串行化「守护轮询」与「手动立即调和」，两者不并发启停。

**D9 fail-safe 默认值。**
控制文件缺失/不可解析/字段非法 → 代理零动作（MUST NOT 猜测期望态），日志留痕。首次部署或
从未下过控制指令时，看护状态不被控制面改写。

**D10 时间与格式约定。**
控制文件 `desired_running` / `requested_at`（ISO8601 +08:00）/ `requested_at_epoch`（Unix 秒）/
`request_id`（`uuid4().hex[:12]`，日志对账用）；与快照同目录、同原子写（tmp + `os.replace`）。
后端与 distro 两侧都按 Asia/Shanghai +08:00 表述。

## Risks / Trade-offs

- [控制生效时延 = 代理轮询间隔（默认 15s）+ 启停耗时] → 页面「切换中」如实展示 + requested_at；
  文档化预期（点击到界面翻转约 ≤ 30s）。
- [`/mnt/d` 9p 文件系统慢/挂起] → 控制文件 <1KB；读失败按「不可解析」处理（不干预）；代理单轮
  异常不退出（沿用采集循环「永不因单轮异常退出」纪律）。
- [控制文件双写者（后端容器 + distro 手动脚本）] → 双方都原子写、last-write-wins；手动脚本只在
  操作员显式动作时写；语义冲突窗口极小，文档化。
- [代理被杀（OOM/distro 重启）] → 快照陈旧 → 页面明示陈旧 + 开关禁用（如实，不装活）；恢复
  步骤入 README（重新拉起代理）；`stop` 脚本的 bash 兜底保证「至少停得掉」。
- [停止中断在途会话] → 与既有手动停止完全一致；半成品工作区任务不进候选（采集器「半块不产出」
  规则，既有契约，不在本 delta 改动）。
- [时区/时钟] → 两侧都写 epoch + 带时区 ISO；pending 判定只比布尔期望/实态，不依赖时钟。

## Migration Plan

1. **distro 侧部署**（README 更新为准）：复制 `factor_research_agent.py`（+ 既有
   `collect_factor_status.py`、三个脚本）到 `/root/`；停旧采集守护 → 起新代理守护（采集不中断，
   看护不重启）；核对快照 `collected_at` 持续推进。
2. **代码面**：后端端点 + 前端开关随 PR 合并；本地/容器（dev override 挂载）重启后端生效。
3. **回滚**：恢复旧 `start/stop-factor-research.sh` 与旧采集守护即可——旧采集器**从不读**控制
   文件，控制文件对旧实现完全惰性；前端/后端回滚随 PR revert。控制文件残留无害。
4. **验证**：E2E（stub 栈）+ 真实栈人工验证（点击 → 看护真停真启 → 恢复原运行态），报告落
   `tests/validation/`。

## Open Questions

- distro 重启后代理需手动拉起（与看护同级）——是否加 Windows 计划任务自拉起，留作后续 ops 项，
  本 delta 不做。
- 控制动作是否需要审计留痕（谁在何时切换）——当前无鉴权体系，request_id + 控制文件时间戳构成
  最小留痕；是否升级为 ops 审计行，留待需求出现。
