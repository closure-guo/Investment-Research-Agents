# Design: extend-factor-library-coverage

> 证据与出处见 `docs/superpowers/research/2026-11-27-factor-library-gap-research.md`；需求见本目录 `specs/`。本文只写「怎么做」与「为什么这样做」。

## Context

因子库是一条「生成器写公式 → 翻译成 DSL → 五道闸 → 入库 → 选股打分」的流水线。2026-11-27 盘点：在册 12 条 active 全是成交量 / 振幅 / K 线形态信号；DSL 只有 6 个价量字段、21 个算子；累计 2444 条候选里 1772 条（72.5%）翻译不进 DSL，其中复杂度超限 814、需要横截面 / 回归 / 大盘 757。外部生成器自 2026-10-29 23:00 起关闭（A2 终裁后既定状态）。

约束（不可动）：

- `market_snapshot` 行不可变；已退市标的历史不得被回填修改（`market-snapshot` 规范）。
- 快照日批 15:31 → 拥挤度日批 15:35 → 选股 15:40 → 衰减监控 15:45 → 内置注册 15:50 → 收割 15:55 的级联时序；快照批次的 65s 同 run 重试余量已贴边。
- 宿主机不得直跑活跃 WAL 库；回填一律容器内执行。
- 自由参数上限 3 不抬（2026-10-19 治理裁决 D4）；|ICIR| 0.3 门槛不降（2026-10-28 杠杆分析）。
- 生成侧契约条款（禁横截面 / 禁矩阵回归 ML）归 `add-cross-section-translation-path`（B1）处置，本 change 不碰。

## Goals / Non-Goals

**Goals:**

1. 让 DSL 能表达四类此前写不出来的构念：事件计数与条件（比较算子）、高阶时序统计、市场残差与全市场聚合、行业中性化。
2. 把已在手或同源可得的参考数据（流通市值、换手率、上市天数、行业门类）接进因子链，且不动 `market_snapshot` 行。
3. 修正自由参数的重复计数，解锁存量复杂度桶里约 398 条候选，上限不变。
4. 新字段带来的新失效模式（数据缺口）全部显式：闸①干净拒收、选股摘要披露、不前向填充。
5. 提案侧知道这些新类型（category 枚举 + 提示词模板）。

**Non-Goals:**

- 基本面 PIT 面板、多 horizon 评估、两融 / 龙虎榜字段、研报因子、横截面转译路径——各自另立或在途。
- 把快照状态位列（涨停封板 / ST / 停牌）开口给 DSL——历史区是写死的 0。
- 总市值字段（无历史）。
- 改变存量 12 条 active 因子的任何读数。

## Decisions

### D1 自由参数按去重数值计数（不是抬上限）

一句话：同一个窗口数字在公式里出现两次，以前算两个参数，现在只算一个；上限还是 3。

- **依据**：存量 814 条复杂度拒译里，501 条只有自由参数一项超限；其中 398 条「Number 节点 > 3、去重后 ≤ 3，且不超深度 / 字段」（占复杂度桶 49%、占全部不可译 22%；按 Qlib 表达式正则计数，未计转译新增数字，真实值略低）。典型形态是 `Mean(ret,20) / Std(ret,20)`——`ret` 子式重复出现，`1` 与 `20` 各被数两次。
- **为什么不抬上限**：D4 裁决三明言「自由参数是过拟合轴……优先评估不增加拟合自由度的表达形态，而非抬上限」。重复出现的相同常数不是独立的拟合自由度——把两个窗口绑成同一个值，搜索空间只会更小。去重计数与该裁决同向。
- **口径**：`count_free_params` 返回 AST 中 Number 节点取值去重后的个数（`1` 与 `1.0` 视为同值；窗口参数计入）；错误消息格式不变（「自由参数 4 > 上限 3」）。只放宽不收紧，存量表达式全部仍合法。
- **备选**：① 上限抬到 4–5——违背 D4；② 具名派生指标 / 宏——改造面大得多，效果相同；③ 公共子表达式提取后按子式计数——等价但实现复杂。

### D2 算子取舍：按点名需求与结构价值选 19 个，其余不做

| 算子 | 类别 | 存量点名（114 条非截面类明细里） | Qlib 映射 |
|---|---|---|---|
| `gt/lt/ge/le/eq/ne` + `if_else` | 比较 / 条件 | 30（条件分支 / 零分母保护） | 有（`Gt/Ge/Lt/Le/Eq/Ne/Greater/Less/If`） |
| `ts_median` | 时序统计 | 17 | 有（`Med`） |
| `ts_skew` | 时序统计 | 13 | 有（`Skew`） |
| `ts_quantile` | 时序统计 | 13 | 有（`Quantile`） |
| `ts_count` | 计数 | 13 | 有（`Count`） |
| `ts_resid` + `cs_mean` | 回归 / 横截面 | 间接（325 条回归残差、112 条大盘收益全灭） | 无（DSL 原生，内部提案可用） |
| `ind_neutralize` | 横截面 | 结构价值（行业相对族） | 无 |
| `ts_arg_max` / `ts_arg_min` | 时序位置 | 3 | 无 |
| `exp` | 逐元素 | 5 | 无 |
| `ts_kurt` / `ts_decay_linear` | 时序统计 | 4 / 1 | 有（`Kurt` / `WMA`） |

不做的：`ema`（无限记忆，与「窗口含 NaN → NaN」口径难对齐，点名 4）、`ts_cov` / `ts_beta`（`ts_corr` × `ts_std` 可派生）、`ts_slope` / `Rsquare` / `Resi`（对时间索引回归，点名 1；映射后会让「禁回归」契约条款自相矛盾）、`tanh` / `sigmoid`（`rank` 可近似）、`ts_var`（`ts_std` 平方可得）。

- **语义统一**：时序算子沿用 `min_periods=window`、窗口含 NaN → NaN；`ts_count` 是唯一例外（它本来就是数非空个数）。比较算子产出 1 / 0 浮点帧、任一侧 NaN → NaN（pandas 原生比较会把 NaN 当 False，须显式传播）。`if_else` 的条件按「非 0 为真」。`ts_quantile` 的 `q` 在解析期校验范围。
- **`ts_resid(y, x, N)`**：逐标的滚动最小二乘的末点残差，用滚动均值 / 协方差闭式向量化（`b = cov/var`，`a = ȳ − b·x̄`），不做逐票循环。配合 `cs_mean` 即得市场残差：`ts_resid(ret, cs_mean(ret), 20)`。
- **`cs_mean`**：当日有效样本 < 30（`MIN_IC_SAMPLES`）→ NaN，防止稀疏字段的「全市场均值」被几只票决定。
- **性能预算**：`ts_arg_max` / `ts_arg_min` 用滑窗视图按行分块实现，避免 (日, 票, 窗) 三维展开；每个新算子在 500 × 5500 面板上的单次求值须与 `ts_rank` 同量级（测试钉死上限）。
- **`ts_skew` / `ts_kurt` 直接用 pandas rolling**，与规范「逐值一致」的锚定口径天然对齐。

### D3 可选参考字段只上 `float_cap` / `turnover` / `listed_days`

一句话：三个字段都有全历史，另外三个看起来现成的字段其实是空壳。

| 候选字段 | 历史可得性（2026-11-27 容器内实测） | 结论 |
|---|---|---|
| `float_cap` 流通市值 | 新浪历史日线带 `outstanding_share`（流通股本）× 不复权收盘价，全历史可得；腾讯批量行情字段 44 给当日值 | 上 |
| `turnover` 换手率 | 新浪历史日线带 `turnover`（小数）；腾讯批量字段 38（百分数）；东财 spot「换手率」列 | 上 |
| `listed_days` 上市天数 | 主表 `list_date` 全量可得，按日派生 | 上 |
| `total_cap` 总市值 | 新浪历史无总股本，只有当日值 | 只落库，不暴露（闸①会长期不过） |
| `limit_up_sealed` / `limit_down_sealed` / `is_st` / `is_suspended` | `scripts/backfill_market_snapshot.py` 在回填区显式写 0，只有最近约 30 个交易日是真值 | 不上（否则 94% 的面板是假 0，闸①还查不出来） |

事件计数改由比较算子从价格派生（如 `ts_sum(ge(ret, 0.095), 20)` = 近 20 日涨幅 ≥ 9.5% 的天数），全历史口径一致。

### D4 参考数据走侧表 + 读路径 LEFT JOIN（不改 `market_snapshot`）

一句话：新数据放一张旁边的表，读快照行的时候顺手拼上去；快照行本身一个字节不动。

- 侧表 `market_ref_daily` 放在**快照库同一文件**里：三处面板加载器（`monthly._panel_from_snapshot`、`monitor._load_panel`、`screening.pipeline`）都已经只拿 `snapshot_db_path`，跨库就得改三处签名；同文件还让衰减监控的面板缓存（按快照库 mtime 键控）在侧表写入后自然失效。
- 附加列在 `read_universe` / `read_universe_range` 的 SQL 里 LEFT JOIN 完成（各仍是单次 SQL），三处加载器零改动。`listed_days` 用 `COALESCE(快照值, julianday 差)` 派生。
- **旧库退化**：侧表 / 列不存在时退回不带 JOIN 的查询。注意现有读路径把一切 `no such table` 映射成 `SnapshotEmptyError`——侧表缺失必须在该判断之前识别，否则旧库会被误判成「无快照」。
- 侧表 DDL 只在写路径 `init_snapshot_db` 执行（读路径 `?mode=ro`、去 DDL 纪律不变）。
- **备选**：① 给 `market_snapshot` 加列并在次日 UPDATE——破坏行不可变；② 另建独立库——三处加载器与缓存键都要改；③ 面板加载后单独再查一次侧表——多一次连接、三处都要加代码。

### D5 增量写入搭拥挤度日批的取数链

一句话：全市场流通市值每天 15:35 本来就在取（拥挤度日批的兜底链），顺手落表即可，不新增网络请求、不新增作业。

- 时序上先于选股（15:40）与衰减监控（15:45），当天的新字段当天可用。
- 现有 `fetch_market_caps_bulk` 只解析字段 44（流通市值）；扩展为逐票返回流通市值 / 总市值 / 换手率（字段 44 / 45 / 38），既有调用方按兼容形态取值。东财 spot 为主源时读「流通市值 / 总市值 / 换手率」列。
- **best-effort**：侧表写入失败只 WARN，不改拥挤度日批自身的「只吞快照不可用、其余上抛」铁律；也不往它的摘要里加字段（不动 `crowding-regime` 规范）。缺口由两条路暴露：选股摘要的 `factor_value_gaps`，以及回填脚本对缺失日期的报告。
- **备选**：① 放进快照日批——腾讯批量约 56 个请求，挤占 15:31 → 15:35 的重试余量（该余量已贴边）；② 新建 15:37 作业——与拥挤度日批重复请求同一数据，且要同步两处 E2E 作业清单；③ 放进衰减监控（15:45）——晚于选股。

### D6 历史走新浪历史日线，容器内回填

- 新脚本 `scripts/backfill_factor_ref.py`：逐票一次调用（不复权口径那条腿），取 `outstanding_share` / `turnover`；`float_cap = outstanding_share × 当日 market_snapshot.close_raw`（当日无快照行则跳过该日，不落半行）。约 5500 次调用，夜间容器内执行，断点续跑 + 幂等 upsert + 源缺列计入 `symbols_failed`。
- 回填区间覆盖快照库全部历史（≥ 准入面板 500 日，并为 2027 年初的 750 日留余量）。
- 换手率统一小数口径（腾讯 / 东财的百分数 ÷ 100）。
- 回填完成后做一次抽样核对：随机若干票的回填末日值与腾讯当日值比对。

### D7 行业中性化做成显式算子，不改全局评估口径

一句话：想要行业中性，就在公式里写 `ind_neutralize(...)`；不写的因子一切照旧。

- **备选（否决）**：在 IC 计算处做全局行业中性化——存量 12 条 active 因子的 IC、权重、衰减判定全部改变，等于回溯翻案，还要重验一遍。
- 行业门类：主表新增 `industry_l1`。主源巨潮逐票（`stock_industry_change_cninfo`，`AKShareClient._fetch_industry_cninfo` 已有降级实现，2026-11-27 实测返回行业门类 / 次类 / 大类 / 中类与变更日期）；一次性回填脚本 + 周一主表刷新分支对缺行业代码增量补抓（best-effort）。批量源（`sw_index_third_cons`、同花顺成分接口）作为探针备选，本机 AKShare 1.18.63 里函数名与文档不一致，须先核。
- **口径声明**：整段面板用同一份最新分类（非时点）。行业变更很少，对去均值的影响有限；将来可升级为按变更日的时点分类。
- 分组语义：当日同行业内去均值；组内有效样本 < 5 或标签缺失 → NaN；面板未携带分组 → 求值报错（不退化为全市场去均值）。

### D8 内置基线包 5 → 7，作为新字段的第一批消费者

- 新增 `size_float`（`log(float_cap)`）、`turnover_20`（`ts_mean(turnover,20)`），与既有五条同走五道闸。它们同时是风格篮子成员（篮子与基线包同真源），风格暴露自动多出两个对照。
- 参考数据未回填时这两条每天在闸①被拒（既有「被拒 builtin 视为缺失、次日可重试」语义），回填完成后自动开始真实评估——不需要人工触发。
- 前端风格标签对未知名原值回退（`STYLE_LABELS[name] ?? name`），无前端改动。

### D9 提案侧只扩枚举与模板，不碰生成侧契约条款

- `CATEGORIES` 由 5 类扩为 9 类（事件状态 / 规模 / 残差 / 行业相对），提示词模板同步算子 / 字段 / 类别 / 计数口径并经 `scripts/deploy_prompts.py` 发布。
- 生成侧契约块（`CONTRACT_RULES` 与算子白名单）不改：白名单由 `qlib_translate` 映射表自动派生，新增的 Qlib 可映射算子会自动出现；`cs_mean` / `ts_resid` / `ind_neutralize` 无 Qlib 映射，不进白名单，因此「禁横截面 / 禁回归」条款对生成侧仍然成立。条款本身的调整归 B1。

### D10 后续 delta 的排序（数据源已探明，机制或裁决未就位）

1. **两融与龙虎榜**（上交所 / 深交所融资融券明细、新浪龙虎榜日报，历史可按日回填，2026-11-27 实测）：复用本 change 的参考数据面。两融只覆盖两融标的，闸①需「在宣称覆盖人群上计缺失率」的值因子口径——即 `add-analyst-revision-factors` 的设计。
2. **基本面 PIT 面板**（新浪财务指标逐票、86 列，实测可得；按法定披露截止日做保守时点近似）：前置是多 horizon 评估。500 日面板对 T+20 做非重叠采样只有约 25 个样本，|ICIR| ≥ 0.3 在统计上不可检验；同时需要把快照历史加深到约 5 年。这是最大的一块空白，也是最重的一项。
3. 研报因子（`add-analyst-revision-factors`，0/10）与横截面转译（`add-cross-section-translation-path`，0/9）直接实施，与本 change 无契约重叠。

## Risks / Trade-offs

- [两次约 5500 票的回填撞上限频或拖长] → 夜间容器内执行、断点续跑、失败票留痕不落半行；行业回填先做 50 票探针（成功率 ≥ 90% 才全量）。
- [新字段引入「数据缺口 → 因子静默归零」的新失效模式] → 三道显式防线：闸①字段预检（`missing_fields`）、选股摘要 `factor_value_gaps`、参考字段一律不前向填充不以 0 冒充。
- [读路径加 JOIN 波及全部快照读方（选股 / 监控 / 诊断 / 回补 / cohort）] → 旧库退化场景 + 「附加列之外逐值不变」回归测试；侧表缺失不得被误判为 `SnapshotEmptyError`。
- [拥挤度日批多一个写库动作] → best-effort、失败不拖垮；侧表与快照同库，仍是单进程多连接的 WAL 形态。
- [计数口径放宽后候选量上升] → 全部仍过五道闸；重放按 60 条 / 批分批进闸。
- [行业标签非时点] → 在设计文档与因子详情口径说明中声明；后续可升级。
- [提示词模板变更] → 必须 `deploy_prompts.py` 发布，否则 eval 门禁拒绝运行。
- [`ts_arg_max` / `ts_arg_min` 内存] → 分块实现 + 性能预算测试。
- [与在途 change 的归档顺序] → 「同构重提桶归属」依赖 `update-harvest-factor-category` 的生产迁移先执行；与 B1 无共同修改的 requirement。

## Migration Plan

1. **P1（纯代码）**：自由参数去重计数 + 19 个算子。上线后重放 translator 阶段的 834 条 `untranslatable`（零 LLM 调用，`scripts/replay_factor_harvest.py`），记录解锁条数与各闸去向。回滚 = revert，存量表达式不受影响。
2. **P2（数据面）**：侧表 / 读路径 / 面板可选字段 / 闸①预检 / 桶归属 / builtin 七条 / 选股披露一次部署 → 夜间容器内回填参考数据历史 → 行业门类探针与全量回填 → 内置注册日批自动评估两条真实口径基线 → 人工验证读数落 `tests/validation/`。回滚：读路径自带旧库退化，侧表与主表新列保留无害。
3. **P3（提案侧）**：category 九类 + 提示词模板 + `deploy_prompts.py`，下次月批（每月 1 日 10:00）生效；distro 生成侧补丁的措辞核对在生成器恢复前完成。
