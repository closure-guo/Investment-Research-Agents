# Design: add-screening-empty-library-fallback

## D1 触发条件：镜像 L2 打分器的拒绝条件，而不是「库为空」

- 打分器 `rank_universe` 的拒绝条件是 `Σ|ic_mean| < 1e-12`（含空因子列表与全零 IC）——与之镜像，
  降级触发 = **无 active 因子，或全部 active 因子无有效 IC 记录**。
- 备选（仅「库为空」触发）否决：因子刚入库、监控尚未写入首条 IC 记录的那一天，L2 仍会拒绝打分 →
  同一失败模式再现（每日中断一次）。镜像条件把过渡窗口一并覆盖，且条件本身在 `ranker.py` 里
  做成公开谓词 `has_scorable_factors(factors, ic_stats)`（与 `factor_weights` 守卫共用同一阈值常量，
  单一来源），避免管道与打分器判定漂移。
- 其余任何异常（快照缺失 / L1 出错 / L3 网关整体不可用 / 池写入失败）不受本通道影响——
  fail-closed 语义原样保留（降级 MUST NOT 成为兜底吞异常的路径）。

## D2 降级排序：近 20 日日均成交额降序，明确「非因子信号」

- 排序键 = L1 已算好的近 20 日成交额序列的有限值均值（`_amounts_by_code` 复用，零新增取数）；
  降序，同额按 symbol 升序（全确定性，与管道无随机数纪律一致）。
- `composite_score` 在降级模式下语义 = 日均成交额（元），`factor_contribs = ()`；前端在 fallback
  模式把该列标题切换为「近 20 日日均成交额（亿元）」呈现——同一数据，语义诚实标注。
- 备选（等权合成/自造 z-score）否决：等于凭空发明一个未经闸口的「因子」，比流动性排序更不诚实。

## D3 披露三处 + 恢复自动

- 批次行 `selection_mode ∈ {factor, fallback}`（幂等迁移：旧行默认 `factor`）；池接口载荷携带
  `selection_mode` 与 `notice`（披露文案单源在后端）；批次历史接口字段随之携带；选股页横幅渲染。
- 恢复：下次日批若库内已有可打分因子 → 同一条代码路径走 `factor` 分支，`selection_mode=factor`
  覆盖当日批次行——无开关、无人工步骤。

## D4 落库口径不变

- 降级批次照常 `rewrite_day_l2_board`（在榜稳定性 `consecutive_days_in_top` 依赖 L2 名单存在性，
  降级名单同契约落库，精选池的「连续 3 日在榜」门槛在降级期照常累计）。
- 失败批次照旧零池（含降级通道内 L3 失败）——批次行与池行仍单事务同生共死。

## Risks / Trade-offs

- 降级期精选池由「流动性 + LLM 粗筛」构成，无量化信号——这是本 delta 明示的产品语义（三处披露），
  不是质量主张；真因子入库即退出。
- 若 IC 记录被意外清空（数据事故），系统会以 `fallback` 披露降级而非 fail——披露可见、可审计；
  与之相比「页面全死」是更差的失效模式（本 delta 的立项理由）。
