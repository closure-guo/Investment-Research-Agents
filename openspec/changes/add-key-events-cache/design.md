# Design: add-key-events-cache

## Approach

**缓存做进 `fetch_key_events` 内部**（方案 A）：所有调用方（选股装配、时效校验、深析 fetch 节点）自动受益，一处实现一处测试。实现要点：

1. **区分「验证过的空」与「失败装的空」是唯一设计关键**。`fetch_events_from_web` 现有返回约定：`None` = 失败（异常/搜索无结果），`[]` = 提取成功但没有 L1/L2 级事件（进 pipeline 后与失败同样落到 L1→L3）。缓存写入以 provenance 门控：
   - 提取成功返回事件列表 → 缓存；
   - 提取成功返回 `[]`（搜索成功、域过滤与提取后确认当日无事件）→ 缓存空列表；
   - `fetch_events_from_web` 返回 `None` 或抛异常 → 不缓存，走既有 L1→L3 降级，下次调用自动重试。
   实现上让 `fetch_events_from_web` 的既有 None/列表约定承载 provenance，`pipeline.fetch_key_events` 据此决定写缓存——**返回值形状不变**，消费方（triage prompt、时效校验、引用校验回声源、深析节点）零改动。
2. **缓存介质**：`DataCache.get_shared_cache()`（进程内共享单例，sqlite、线程安全），key `{code}:key_events`、TTL 86400——与深析 fetch 节点既有的同名 key 同值幂等写，两侧语义天然对齐（深析节点的缓存层变成无害冗余，不拆除）。测试经 `DataCache(db_path=…)` 显式注入，不触生产 cache.db。
3. **`use_web_search=False` 不读不写**：显式关闭搜索的调用方要的是确定性零网络路径（L1→L3），缓存命中反而引入隐式网络产物。深析节点开启搜索时仍各自持有一层缓存——两级同 key 幂等，无行为冲突。
4. **白名单**（`events/config.py::ALLOWED_DOMAINS`）扩 6 域：`cls.cn`（财联社）、`xueqiu.com`、`news.qq.com`、`investing.com`、`yicai.com`（一财）、`nbd.com.cn`（每经）。均为新闻/资讯源；行情页域（cfi.cn、9fzt.com）不入选，避免稀释喂给 LLM 的摘要质量。
5. **传名**：`_assemble_events_by_symbol(candidates)` 增加名字来源参数（生产调用点传 `names_by_symbol`，批内现成；测试注入处不破签名），`screening_freshness_removals` 同样从快照行取 `name` 传入。缺名降级纯代码查询，仅记 warning。

## Alternatives Considered

- **方案 B：只在选股链两个调用点各自加缓存**——波及面小，但缓存逻辑写两份、深析链不共享、未来新调用方继续裸跑，无真实优点。不选。
- **方案 C：池成员每日事件预构建批（独立 job 落 key_events.json）**——把事件变成离线资产、效果最强，但需新建调度链路与存储；方案 A 落地后收益边际化。YAGNI，不选（留作后续若池规模扩大再议）。

## Risks

- **缓存毒化**（把当日瞬时故障的结果缓存住，全天错误）：由 provenance 门控消除——只有「完整走完搜索+提取」的结果可缓存；兜底卡永不缓存。测试逐分支钉死。深析 fetch 节点侧原有无条件 `c.set`（终审 C1）已拆除，兜底卡不再经节点写入共享 key。
- **批后新事件遮蔽（时效性取舍）**：15:40 批写入的缓存（含验证过的空）当日不再回源，会遮蔽「批写入之后至次日缓存过期前」真实新发的事件；时效校验借事件清单发现新发重大事件的排雷窗口因此收窄到缓存建立之前。实现符合 spec（同日命中不回源是缓存的本意），显式接受该取舍；若后续需要实时排雷，候选方向=freshness 侧短 TTL 或旁路（绕过缓存对池成员做轻量增量核查）。
- **验证过的空遮蔽 L1 预构建库更新**：缓存命中（含空）当日不再回源，若 key_events.json 同日新增该股数据会被遮蔽至次日。预构建库为静态 demo 文件、更新频率≈0，接受；design 层显式记录该取舍。
- **白名单扩集稀释提取质量**（更多摘要喂给 LLM 反而提不出重点）：只加新闻/资讯域，不加行情页域；提取 prompt 口径不动。生产读数（「不可用」占比）部署后观察，异常则回退名单。
- **cache.db 路径与并发**：`DataCache` 单例已在生产承载深析缓存（9-08 审计后线程安全）；选股批并发 3 下写入为微秒级锁竞争，无新风险。测试一律显式 `db_path` 注入，不触宿主/容器 cache.db（9p 视图分裂教训）。
- **首日种子成本**：部署后首个 15:40 批仍全额支付 100×~20s——与现状相同（现状是每天全额支付），无回归；自次日起降至每日新增候选量级。
