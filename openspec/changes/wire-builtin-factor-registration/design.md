# Design: wire-builtin-factor-registration

## Context

「builtin 因子注册路径」Requirement 存在、机制实现存在（`register_builtins`，五道闸准入 + 闸 0 结构查重幂等），但缺**触发入口**：验收脚本（10-13，合成面板）之外无生产调用方。因子库的另一个供给方（LLM 提案月批）在真实数据上无兜底能力（全数被拒即库空）。本 delta 补入口与幂等/失败语义，不改五道闸本身。

## Goals / Non-Goals

- Goals：给基线包一个生产注册入口；幂等且不回填 retired；面板不可得 fail loud；准入结论逐条可观测。
- Non-Goals：不改闸①缺失率口径与面板深度（issue #345 的 ② 裁决项，另行处理）；不改提案路径；不做启动期注册（见 D1）；不手工灌注生产库。

## Decisions

### D1 入口 = 日批 job（非启动路径）

启动路径（同 `init_db` 先例）否决：`init_db` 先例只覆盖**建表**（零数据依赖、幂等廉价）；而 builtin 注册需要**快照面板**（数据依赖）且执行五道闸准入（重操作、含闸③置换检验）——启动不应做数据依赖的重准入，且启动时快照历史不足将导致注册被推迟到一个未知时点。日批通道自带调度 / 运行历史 / 单飞锁 / 手动补跑（运维可即刻引导），语义完整。

### D2 日批（15:50）而非月批

- 排程位置：快照 15:30（面板数据就绪）与因子衰减监控 15:45 之后、结算链（16:00 起）之前——不竞争资源、不打断结算。
- 频度选择日批的理由：**存在性检查零成本**（不建面板即可 skip），全量注册完成后每日空转成本 ≈ 一次库查询；库空 / 缺条目时次日即自愈（无需等月初或人工补跑），且真实面板的准入结论可随市场状态演进逐日重检（确定性失败重试无副作用——被拒条目不入库、无状态变化）。

### D3 存在性幂等语义：任意状态视为已注册（含 retired）

跳过判据 = 库内存在**同表达式**条目（`list_factors` 全量，任意状态）。与闸 0（`candidate/active/degraded` 查重、retired 可重提）的边界：**「retired 可重提」属提案路径语义**（LLM 提出新假设重走准入）；基线包是固定表达式，注册任务 MUST NOT 复活被衰减监控退役的条目（否则日批注册与衰减判定会逐日互斗）。结构等价但字符串不同的条目由闸 0 兜底（提交后被 STRUCTURAL_DUPLICATE 拒收，不重复入库）。

### D4 面板口径与失败语义

面板构造沿用 `monitor._recent_trade_dates` / `_load_panel`（`_PANEL_LOOKBACK_DAYS`，取数口径单一来源——与提案月批同款）；面板不可得（快照库空 / 历史不足）→ `ValueError` 上抛（job 记 failed 留痕）。**仅缺失条目存在时**才构造面板（全量已注册 → 不触面板，快照库不可达也不失败）。

### D5 `register_builtins` 增 `factors` 参数

任务只提交缺失子集（默认 `None` = 全量五条）——避免对已注册条目重复走闸（尤其 retired 条目）。既有调用方（验收脚本）零改动。

## Risks / Trade-offs

- 真实面板上多数 builtin 可能被拒（闸①热身期缺失率 / 闸②弱 IC）：本 delta 只保证「入口存在 + 结论如实」；能否入库取决于面板深度与市场数据（② 裁决项）。摘要的 `reasons` 逐条可查。
- 每日重试确定性失败（如长窗因子恒 LOW_COVERAGE）：成本 ≈ 一次面板构造 + 5 条因子评估（秒级），可接受；换来的是数据/口径改善后的次日自动生效。
