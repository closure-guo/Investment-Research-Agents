# Proposal: fix-price-gate-meta-discourse

## Why

决策价位交叉校验在 2026-10-02～10-22 阻断 32 次报告交付。逐条取证（Langfuse trace 还原 22 条原文）后，其中 6 条的数值不是终稿的价格主张，而是模型**复述上一轮打回消息**或**引述被驳回方案**：

- 「此前价位冲突系'MA60'（60日均线）被误读为数值价位60所致」（600845 10-05、10-06 两连阻断）
- 「系统打回消息称『文本价位 300 与近期高点 245.48 偏差 22.21%』」（300033 10-13）
- 「终稿中出现的『20』为考核窗口的期数表述」（600015 10-13）
- 「激进方的试探仓（止损 21.5…）…不予采纳」（601066 10-20）

校验器把这些数字当作新主张再次比对，形成「打回 → 复述 → 再打回」的自我强化回路：打回反馈本身制造了下一轮阻断的输入。

## What Changes

- 新增句子级豁免：数值所在句子（以 `。；！？` 与换行分句）含 `打回/误读/校验/修正/澄清/价位冲突/待核实/恶化/上一稿/上一轮/驳回/不予采纳/rejection/corrective/reject` 任一标记时，该句内数值不进入价位校验（主循环与方向预扫同口径）。
- 正常行情陈述句不受影响（护栏测试：同段「放量突破 25.0」照常登记偏差）。
- 阈值、参考带豁免、打回一次 / 未恶化放行 / 恶化阻断的门禁分层均不变。

## Capabilities

### Modified Capabilities

- `price-level-tooling`：新增「元话语与自引用句不参与价位校验」。

### New Capabilities

（无）

## Impact

- 代码：`src/finance_agent/metrics/decision_price_check.py`（`_in_meta_discussion` + 两处循环跳过）。
- 测试：`tests/metrics/test_decision_price_check.py::TestSelfReferenceFalsePositives`（4 例，含护栏）。
- 行为：自引用类误报阻断消失；代价是「含元话语标记的句子里若同时出现真实错误价位」不再拦截——由同文本的触发器/结构化字段承担校验（护栏已覆盖）。
