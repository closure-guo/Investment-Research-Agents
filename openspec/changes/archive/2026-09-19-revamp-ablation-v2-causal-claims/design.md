# Design: revamp-ablation-v2-causal-claims

## Context

v1 消融（`evals/ablation.py` 三变体 × judge 四维层增量）已完成使命并自证失效：n10 权威批次 90 run 全维 CI 含 0，报告自身披露有效 n=3、#112 伪影存活、judge 未校准三重缺陷。裁剪决策（辩论层 +7.9% / 决策+风控层 +30.1% / 全裁省 28.7% token）悬置中。本设计源自《消融实验框架 v2.1 设计方案》（2026-09-15），经对仓库现状逐条核验后修订为 v2.2。

**现状事实基线（核验结论，v2.1 声明 vs 实际）**：

## Goals / Non-Goals

**Goals:**

1. 建立因果主张登记表准入制度与两族实验（A 注入法 / B 编排层价值）的指标管线；
2. 统计纪律工程化：预登记、阳性对照、结论两句式带 MDE、聚类 bootstrap、结论注册表；
3. 工程前置收口：F0 后半（驱动薄壳化）、F3（citation 腿换拆报口径）、F8（结论注册表）。

**Non-Goals:**

- 不唤醒休眠机制（`CITATION_AUTO_RETRY_ENABLED=False` 的定向重试/coverage 打回不进矩阵；评估须先立独立 delta 唤醒）；
- 不修改 `agent-evaluation-suite` 幻觉率三态判定契约；不修改运行时五层管线行为；
- 不在本 delta 内执行 P1/P2 跑批（本 delta 交付框架与 P0 收口，跑批按预登记另行立项）；
- B6（事后结算）不作层间归因证据，仅作 full 绝对质量线与未来裁剪的版本分段对照——track-record 历史 predictions 全产自 full 变体，无法层间对比。

## Decisions

### D1：指标准入判据 = 因果下游检验（替代 judge 四维通吃）

判别一个指标能否进消融矩阵的唯一标准：其失败模式是否**因果地依赖**被消融对象。切题度不依赖辩论层 → 出局；风控数字出处率依赖决策+风控层 → 入选。登记表（A1–A7 / B1–B6，每行含因果主张/失败模式/主指标/判定方式/效应量预期）是准入工件，无主张不进矩阵。

*替代方案否决*：继续用 judge 四维但换更大样本——n10 已证明天花板即目标态，扩样只会在更低处贴着 0。

### D2：族 A 用注入法而非移除法作为主轨

自然分布真幻觉≈0（r2 终裁 0/565），移除法无信号可拦。注入法复用已有设施：`tests/test_citation_rework.py:268` 的「故意改错一个数字必须 FAIL」门禁即雏形，8 类污染类型对齐 citation 校验器 FAIL 桶与 incidents 实证失败模式（020/022 契约疾病、026 归因、027 价位）。

**注入点分层**（同时验证机制-失败模式对应关系本身）：context 层（测输入侧+校验侧联动）/ 分析师输出层（绕过输入侧直测校验侧）/ 决策层（测 A5）。**成本结构二分**（v2.2 修订）：
- **离线重放型**（A3/A4 校验侧机制）：对已有产物 JSON 做污染 + 重放校验器，零 LLM 成本——P1 主体；
- **真跑型**（输入侧联动 + A5 决策层价位）：全管线 run——P1 中限量（每标的 × 每价位污染 1 实例 pilot）。

*替代方案否决*：移除法主轨——结构注定全阴性（v1 覆辙）。移保留为 P2 的背景证据轨（10 标的 × 关机制 × 自然输入，回答「当前自然分布下还在挡子弹吗」）。

### D3：逃逸率终裁分母与误报分离（incident 026 纪律的延伸）

逃逸 = 污染值原样出现在终态产物**且**经人工终裁确认为真逃逸。校验器误报（机制关闭时 FAIL 误报被计作「拦下」）走四桶拆报口径（blocked / analyst_true_fail / surgical_repaired / verifier_normalized），不进逃逸率分母。终裁成本显式入预算：P1 pilot（10 标的 × 32 单元 × 2 态）预估终裁量 ≤ 若干百条，owner 逐条裁决落 `tests/validation/`。

### D4：单元级判定落库 + 标的聚类推断

判定单元 = claim / 风险点 / 执行参数 / 价位（每份产物拆 20–50 单元），落库字段 `unit_id, ticker, run, variant, unit_type, judgment, method(code|nli|judge), confidence`。推断单元 = 标的（聚类 bootstrap 重采样簇，B=10,000，复用 `evals/stats.py`）。设计效应如实报告：ICC=0.1 时 20 标的 × 30 单元有效 n≈154（7.7 倍而非 30 倍）。禁止把重复折叠成中位数再配对。

### D5：LLM 参与判定的校准门控全覆盖（v2.2 修订）

v2.1 只约束 B2/B5，但 B1 的「被决策吸收」NLI 判定与 B3 的「NLI 补方向」同样有 LLM 参与且 B1 是辩论层**主指标**。校准义务扩展为：凡 `method=nli|judge` 的判定维度，该批 rubric 与人工一致率 ≥80% 才允许进消融结论（复用 `evals/judge_calibration/` 的 need_calibrate 触发器），20% 单元人工复核，一致率 <80% 该批作废重校准。

### D6：统计结论只有两种合法句式

① CI 整体低于决策阈值 →「在本实验分辨率（MDE=X）下，该对象增量低于其成本对应阈值，建议降级/裁剪」（真阴性）；② CI 同时跨 0 和阈值 →「分辨率不足，需扩至 N 只标的」（悬置）。裸「未获统计支持」不合格，必附 MDE。阳性对照义务：每轮跑批带关 verify_citations 的已知劣化变体，测不出显著差异 = 本轮全部阴性作废。

**决策阈值须附换算依据**（v2.2 修订）：B5「胜率 ≥60% 对应 +41% token」须给出换算式（如：pairwise 胜率 60% ≈ 报告质量优势可折算的期望决策增益 ≥ 边际 token 成本，依据预登记时声明的成本-效用曲线）；B1「≥1 个有效新增风险点/只对应 +7%」同理。预登记文档中缺换算依据的阈值视为未登记，该轮跑批不得启动。

### D7：结论注册表（F8）

evals 报告头部必带 `status: active | superseded-by: <path>`，docs/evals 索引渲染状态徽章。报告的结论是有生命周期的（会被后续批次推翻），文档是静态的——注册表把「哪个结论当前有效」变成可查询状态而非考古工作。存量报告（pilot.md 已标 superseded-by、n10 已标 active）为首批注册对象。

### D8：工程前置只承接三项（与在途 delta 对账后）

- **F0 后半**：`ablation_pilot.py` 的 judge 判分/judge_vars 落盘逻辑移入库侧函数（维度过滤已收口，判分/落盘仍留驱动侧 `run_one_costed`）；驱动只保留续跑/记账/coverage 包装。
- **F3**：消融表 citation 腿废弃旧 `citation_pass` 标量，换四桶拆报口径。
- **F8**：D7 的结论注册表。

排序约束：本 delta 的 `evaluation::数据对齐消融实验` MODIFIED 须 rebase 在 `update-ablation-driver-parity-and-report-status` 收口合并之后（project-workflow §6）。

### D9：机制价值两栏（暴露率 × 拦截率）与族 A 三层分工（v2.2.1，P1 round-3 实证驱动）

**框架级收获**：一个反幻觉机制的期望价值 = **暴露率**（它负责的失败模式实际发生多频繁）× **拦截率**（发生时它能拦住多少）。注入法测的是拦截率（条件于暴露发生），此前登记表缺暴露率一栏——缺了它，拦截率表会被误读成机制价值排行榜。登记表（`evals/causal_ablation/claims.py`）每机制增两栏：`exposure_metric`（暴露率及其测法）+ `exposure_source`（数据来源）。A5 是首个实证：拦截率面全 void（决策层无可执行价位可查）而暴露率 ≈0 → 期望价值趋零。

**族 A 三层分工**（各司其职，职责不得互换）：

1. **离线构造层**（出拦截率统计结论，便宜/确定/可进 CI）：
   - 合成构造：手写 claim（像 direction/unit），最确定但分布失真 → 只作稀有污染型的补充；
   - **冻结重放（推荐）**：污染 context 下**真跑一次分析师并把 claim 列表落盘冻结**，该冻结 claim 再分别走 verify_citations 开/关两态。分析师输出保留真实分布，机制对比完全确定（两态只差机制这一个变量）——retrieval-equalized 原则在管线边界上的对应物：**在机制上游边界冻结，在机制下游对比**。
2. **真跑端到端层**（降级为**链路通畅冒烟**，不做统计）：有效对 = 两态都到达产物 **且** 判定可归因；1~2 个有效对即过。P1 round-3 的两条 000001 有效对证明了「污染能到达校验器、开态处置链路生效」，这就是该层全部职责。
3. **B4 遥测层**（出暴露率，长期自然流量）：暴露稀缺的机制，正确仪器是自然流量长期观察而非注入——低频、高单价、事件驱动，不是比率。

**A5 结论两联**（缺一不可）：①「默认 query 下可执行价位**暴露率实测 0.25**（20 标的全图真跑：buy 4 / sell 1 / watch 14 / hold 1）——早期 3 标的「全 watch」系小样本巧合，已修正」→ 登记为**系统事实**；②「sanity 回路在真实 buy/sell 决策上的触发/修正读数」→ B4 遥测长期跟踪（并可用 5 个可执行标的直接注入测拦截率）。B4 与注入法同样依赖暴露：若生产决策也全是 watch，B4 同样长期读零——故 ① 必须先立。

**连带影响（族 B 功效反算）**：实测可执行率 0.25 → B3（风控数字出处率）分母按 25%（而非早期担心的趋零）反算、B5 pairwise 的区分度不受影响。**P2 开跑前先用一周生产流量统计决策动作分布（buy/sell/watch），族 B 所有暴露相关指标的 MDE 以它为输入重算。**

**真跑配对可比性前提（P1 round-3 缺陷修复项）**：真跑型配对的 SHALL 前提是**两态都到达产物**——单态未到达（如该趟采样未引用被污染字段）按 `void_injection` 处理，SHALL NOT 按 spec letter「不含该值 = 拦下」记成拦截（与离线腿 `path_unresolvable` 伪拦截同类）。

## Risks / Trade-offs

- [注入强度两极化：太易全拦（逃逸率全 0 无方差）/太难全穿（全部逃逸也无信息）] → P1 先 10 标的 pilot 校准强度；McNemar 不一致对子比例 <10% 时重校注入参数而非硬跑 20 标的。
- [机制开关的「关」不干净：机制间共享代码路径（如 A3 verify_citations 同时服务 A4 修复回路），关一个可能连带关另一个] → 每机制的开关点在预登记文档中登记到具体配置项/函数级别，pilot 阶段用遥测（span stats）验证开关只影响目标机制。
- [A5 前置不确定：027 修复后价位回路的真实触发率未知，效应量预期可能落空] → A5 的 P1 指标先以「修复后遥测基线」为门槛：无触发记录则该机制标「自然分布休眠」，进 P2 移除轨而非注入轨。
- [终裁成本超预算：逃逸率统计依赖人工逐条终裁，与 incident 026 的 22 条待终裁积压叠加] → 终裁量上限写入预登记停止规则；超限即收窄污染矩阵而非放宽终裁。
- [B1 的 NLI 吸收判定语义等价标准模糊（什么算「同一风险点」）] → 差集提取给原文对，NLI 只判二值等价；边缘案例进 20% 人工复核桶，校准一致率 <80% 整批作废。
- [judge 校准漂移：round7 达标（09-13）后 rubric 再演进，消融跨轮不可比] → 每轮预登记锁定 rubric 版本号；跨轮比较须同版本或有版本分段声明。

## Migration Plan

P0（本 delta，零 LLM 成本，1 周量级）→ P1 注入法 pilot（10 标的，离线重放型为主）→ P2 族 B 20 标的（分层抽样，复用 `evals/backtest/sampling.py`；移除轨背景证据同行）→ P3 track-record 长期线（免维护）。每期跑批前预登记文档入库 `evals/ablation/preregister/<date>.md`。回滚：框架为纯评估侧增量，不影响运行时；任一期结论不可靠时按 D7 标 superseded 即可，无代码回滚需求。

## Open Questions

1. B5 pairwise 的 judge 用哪个模型（deepseek-v4-flash 沿用 vs 与分析模型进一步隔离）——P2 预登记时裁决；
2. 注入矩阵的事实型 claim 路径（事件编造污染）是否需要 LLM 生成假新闻标题，还是人工 fixture 固定集——P1 pilot 时按「确定性优先」原则先试固定集；
3. F0 后半薄壳化的库侧函数归属（`evals/ablation.py` 内新模块 vs 独立 `evals/ablation/driver_lib.py`）——实现任务卡时定，倾向前者（消融入口唯一化）。
