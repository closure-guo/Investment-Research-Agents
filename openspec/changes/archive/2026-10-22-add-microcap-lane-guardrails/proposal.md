# 小票通道与含退市股池（add-microcap-lane-guardrails）

## Why

2026-10-18 调研结论：容量租金区（低流动性小市值段）是个人相对机构的主战场，但直接下沉有两个前置缺口——① 回测池缺退市股（幸存者偏差：2026-10-15 对标备忘录已列为 ❌），② 无拥挤度护栏（本程序变更 2）。当前 L1 以单一档位（日均成交额 ≥ 5000 万）全局剔除低流动性标的，这是护栏但也等于主动放弃个人优势区。本变更是该程序第 4 项前半：**先把前置与观察通道建对，再谈接通执行**（顺序见调研备忘录 §4.2）。

## What Changes

- **含退市股历史池（新能力的一部分）**：退市标的清单抓取与 `security_master` 扩展（退市标记 + 退市日）；价格历史可得时补采；池构建支持含退市标的（时点可见性 = 上市日 ≤ t ≤ 退市日）；无价格历史的退市标的如实标注缺失；防幸存者偏差回归测试。
- **小票通道约束档位**：`screening/constraints.py` 扩展档位（`microcap`：流动性阈值默认 1000 万、其余同主档）；常量仍单一来源；主档默认行为逐字节不变。
- **通道批次产出（observation_only）**：小票通道按独立档位产出批次记录（含 `pool=microcap` 标注与建议执行约束：单票上限默认 5%、滑点档位提升），**v1 不接入执行链**（不产生订单）；批次产出 SHALL 受前置门禁约束：退市股池就绪 + 拥挤度数据就绪，缺前置时批次标记 `observation_only` 并披露缺失前置。
- **展示标注**：精选池/批次数据中新增 `pool` 与前置状态字段（供 API 与后续页面消费）。

## Impact

- 代码：`data/`（退市清单抓取、主表扩展）、`screening/`（constraints 档位、filters/pipeline 档位参数、批次标注）、`outcome/scheduler.py`（通道日批）。
- 数据：`security_master` 扩展列；退市价格历史补采（可得范围内）。
- 行为：主通道行为零变化（档位默认值同现状）；小票通道纯增量观察产出。
- E2E：不新增页面（v1 无 UI 变更），E2E 不适用；以单测/集成与人工验证（批次数据核对）为准。
- 非目标：**不接入执行链**（不产生订单、不改单票 20% 主档语义）——执行接通由后续变更在观察期读数通过后单独立项。
