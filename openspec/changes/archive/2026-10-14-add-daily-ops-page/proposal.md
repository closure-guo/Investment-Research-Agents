# Proposal: add-daily-ops-page

## Why

日批是系统的「心跳」——快照 / 选股 / 因子监控 / 判定 / 执行 / 仿真结算 / 盯市 / 指标快照 / 完整性 / cohort 十条任务分布在 15:30–18:00。现状：全量控制台在「设置 → 评估运维」（面向配置与全量操作），选股页只看到池；**缺一个「今天各批一眼看全 + 失败原因 + 快捷补跑」的当日视图**。设计系统 proposal 的 7 页面愿景明列「日批运维」页（PageShellD：批次列表 + 步骤级状态图标）。

## What Changes

- **后端**：`GET /api/screening/batches`（选股批次历史：日期 / 状态 / 各层计数（l1_passed/l2_top/l3_keep）/ 池数 / 错误 / 起止时间）。
- **前端 `/ops` 页**（PageShellD）：
  - **当日时间线**：按排程时刻排序的全部日批任务（数据驱动，不硬编码），每项含 步骤级状态图标（成功 / 失败 / 未跑 / 运行中）、最近运行摘要、失败原因逐字、一键补跑按钮（复用既有补跑端点与 409 语义）；
  - **选股批次历史表**：近 N 批次（日期 / 状态 / 各层计数 / 池数 / 错误），失败批次标注原因；
  - 与评估运维页分工：本页 = 当日聚合 + 快捷补跑；cohort / 回测 / 健康检查 / 预登记等全量控制仍在评估运维页，页面提供跳转链接。
- 入口：侧边栏折叠图标 + 命令面板。

非目标（Out of scope）：

- 不迁移/复制评估运维页的全量控制能力（只加跳转）。
- 不做告警推送（微信/邮件等，属后续）。
- 不做历史批次的图表化趋势（先表格）。

## Capabilities

### New Capabilities
（无）

### Modified Capabilities
- `stock-screening`: 新增「批次历史查询」要求。
- `frontend`: 新增「日批运维页」要求。

## Impact

- **后端**：`screening/store.py` 新增 `list_batches` 读函数 + `api.py` 只读端点。
- **前端**：`frontend/src/pages/ops/`（新页）+ 路由 + 入口。
- **测试**：API 单测（历史字段/空库）；前端 Vitest（时间线排序/状态图标/补跑按钮/批次表/空态）；Playwright E2E（stub 种子：两批次一成功一失败 + 任务时间线）。
