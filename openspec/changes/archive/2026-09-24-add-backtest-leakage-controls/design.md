# Design: add-backtest-leakage-controls

## Context

回测设施已建成并试跑（`evals/backtest/`：data_snapshot as-of 截断、replay 全图重放 ×3、performance/block bootstrap 显著性、baselines 四基线、sampling regime 分层；spec 五条需求齐备）。缺口不在通路而在**效度**：模型可能「记得」历史走势，深历史回测的 skill 主张不可信；且规范层面存在前复权/后复权矛盾、回测批未接预登记与结论纪律。Δ1 已把回测腿定位为「快但带泄漏风险」的读数腿、forward 腿为金标准，本 delta 给回测腿装上效度护栏。

## Goals / Non-Goals

**Goals:**

- 让「回测读数可信到什么程度」变成可披露的实证量（探针命中率），而不是默认假设
- 消除复权口径的规范矛盾与 as-of 保真破坏
- 回测批接入项目已验证的纪律机器（预登记 / 两句式 / status 头 / 索引渲染）

**Non-Goals:**

- 不追求「完全消除泄漏」——参数化记忆无法根除，只能探测、披露、降级句式；金标准地位留给 forward 腿
- 不改分析输入路径的复权口径（分析师看的数据是另一个问题，本 delta 只管结算/回测收益计算路径，输入路径核对结果如实披露）
- 不裁决正式批的样本量与预算（owner 决策点，预登记时定）

## Decisions

**D1 干净窗口 = 「T+20 可结算」硬条件 + 「探针披露」软条件。**
硬条件保证读数可结算（决策日距跑批日 ≥ 主窗口交易日数）；软条件承认模型 cutoff 不可精确知晓——不用「cutoff 日期」做硬边界（各模型 cutoff 不公开且随版本漂移），改用探针实测记忆命中率做实证判定。深历史批次（如 2023）不禁止跑，但永久定位「通路验证」：其价值是验证设施，不产 skill 结论句。

**D2 探针设计：三层问题 × 真值对照。**
对候选窗口抽样标的（每批 ≥10 只 × 3–5 问）：① 方向题——「T 日之后 20 个交易日该标的相对大盘涨跌方向？」；② 幅度桶题——涨跌幅落在哪个桶（±2% 带同源分桶）；③ 事件题——该窗口内标的是否有重大事件（并购/暴雷/政策，真值取自新闻数据）。真值由 akshare 后复权序列与既有新闻源离线构造，模型在**无 as-of 快照输入**的裸问条件下作答（模拟「它记得多少」）。记忆命中率 = 答对占比（方向题为主指标，事件题为辅证）。命中率 > 阈值（预登记，建议 60%）→ 批次降级句式「泄漏污染下的上界证据：真实 skill ≤ 读数」。阈值语义：60% 显著高于随机（方向二分类 50%），说明模型对该窗口有可用记忆。

**D3 复权统一到后复权，仅动结算/回测取数路径。**
后复权的历史价格 = 当时真实成交价（复权因子向未来累乘），as-of 保真；前复权以今日为基追溯改写历史价，快照截断后的价格序列 ≠ 决策时点可见序列。`decision-outcome` 主规范已写后复权，`decision-backtest` 的前复权文字属同步遗留矛盾，本 delta 修正文字并把结算/回测取数切到后复权序列；同时核对生产结算 job 的实际复权口径（若 fetch_kline qfq 被结算复用，属存量 spec-实现漂移，一并修正）。分析输入路径（分析师看的 K 线）复权口径不动——改它会移动全体分析师的行为基线，需独立 delta 与观测电池对照。

**D4 regime 冲突条款：干净窗口优先，结论限定不外推。**
干净窗口（近端 ~1–3 个月）大概率只覆盖单一 regime，与「三 regime 各 ≥10 标的」冲突。取舍：宁可 regime 覆盖不全 + 结论限定（「本轮读数仅适用于震荡市」），不可为了分层去碰深历史（泄漏污染整批）。这与 `decision-backtest`「SHALL NOT 仅在单边行情样本上汇报绩效结论」的原始意图兼容——原意是防 cherry-pick 单边行情，披露 + 限定结论即满足；跨 regime 的完整拼图由 forward 腿随日历自然积累（cohort 跨越行情周期）。

**D5 纪律机器全部复用，不另造。**
预登记 = `evals/ablation/preregister/` 格式与解析（门禁字段 `OUTCOME_REQUIRED_FIELDS`）；status 头 = `causal_ablation/report_status.py` 校验 + `docs/evals/README.md` 索引渲染。回测报告模板加固定段落：探针读数 / 干净窗口判定结果 / regime 覆盖披露 / 预登记指针。

**结论句纪律的实际落点（终审修正，2026-09-24）**：回测结论句由 `evals/backtest/report.py::build_conclusion` 单独实现（唯一生成点），产出四种形态——sanity 不通过的覆盖句 / skill 句（含 regime 限定后缀）/ 探针超阈降级句「上界证据」/ 通路验证句。Δ1 的 outcome 两句式（显著方向=效应量+CI｜分辨率不足=MDE+扩样方向，`evals/outcome/conclusion.py`）**尚未接到回测结论句**：回测的 skill 句当前由 `_conclude(sharpe_ci)` 产出（超额 Sharpe 对比句），不经 `assert_outcome_sentence_legal` 校验。**首个正式批的预登记必须固定该批结论句的形态（含效应量与 CI/MDE）并接上 Δ1 守卫**——属 owner 待办，不在本 delta 实施内（本 delta 无正式批实跑，风险未落地）。

## Risks / Trade-offs

- [探针本身被模型「察觉」而策略性作答] → 裸问条件（无快照输入）+ 方向/幅度/事件三层交叉，单层失真可被层间不一致暴露；探针结果如实披露不做净化假设
- [近端窗口样本受单一 regime 支配，读数外推性弱] → D4 限定句式 + forward 腿互补；两腿互证（Δ1）是最终采信机制
- [后复权切换改动结算数值（分红除权样本）] → 存量已结算行不重算（Δ2 D4 同款切点纪律）；切换日前后读数分段披露
- [探针真值构造依赖新闻源历史可得性] → 事件题为辅证、方向题为主指标（akshare 价格序列稳定可得）；事件真值不可得的标的计未知占比披露

## Migration Plan

1. 修正 decision-backtest 复权文字与结算取数路径（含生产结算复权核对），切点登记
2. 探针模块 + run_backtest 干净窗口校验 + 报告模板段落
3. pilot-2023-shock.md 就地补 status 头与泄漏标注（原文与数字保留）
4. 首个正式批 = owner 批预算 + 预登记生效后才可开跑（不在本 delta 实施范围内强跑）
回滚：探针与窗口校验为报告准入装置，关闭即回到旧行为（但旧行为 = 无泄漏护栏，不建议）；复权切换按切点分段可追溯。
