## 二、最重要的新发现：买入观点自 2026-10-08 起归零

**数据**：按日统计「当日处于 open 状态的 buy 观点数」——

```
2026-10-07   5
2026-10-08   0   ← 从此再未出现过
...
2026-11-04   0   （当日 open：中性 179 条、卖出 58 条、买入 0 条）
```

**代码路径**：`execution/driver.py::_create_signals_from_decisions`

```python
predictions = list_predictions(status="open", ...)   # 只扫 open
...
if created_at[:10] >= effective_date: continue        # 当日及更晚不执行
if str(payload["fund_manager_verdict"]) != "approve": continue
signal = signal_from_decision(...)                    # buy→long，sell/hold/watch→flat
```

- 13 条 buy 观点里，11 条在 1~3 天内被同标的的新观点 `superseded`，2 条 `missing_entry_price` 不可判定；
- 执行线自 2026-10-13 才开始产信号，彼时已无任何 open buy。

**结论**：`paper_equity` 14 天恒为 1,000,000、0 笔成交，**不是执行链路故障，是系统已经 27 天没有给出买入建议**。
这条比净值口径更值得优先查：它意味着策略当前的实际立场是「空仓 + 看空」，而净值曲线把这个立场表达成了「满仓做空」。

## 三、三个待修缺陷（与口径无关）

| # | 缺陷 | 证据 | 建议修法 | 风险 |
|---|---|---|---|---|
| 1 | 同一标的可同时挂多条 open 观点，各自 1/N | 南方航空 10-22~10-26 两条并存（各 50%）；11-04 三条并存 | 聚合前按 symbol 归并（取当日最新一条，与 `duplicate_of_day` 同日口径一致），再 1/N | 改变净值读数 → 需口径登记 |
| 2 | `short` 的 `target_price` 可高于入场价 | 10-27 南航 short entry 4.80 / target 4.95 | 落库校验：short 的 target 必须 < entry（或改名 stop_price 并显式建模） | 可能误伤「再评估位」语义 → 先人工确认字段定义 |
| 3 | `excess_return` 几乎全空 | 337 条中 15 条非空；5 笔已结算全 null | `superseded` 结算补基准腿（现仅 horizon 结算算基准） | 需确认 spec 是否允许 superseded 带超额 |

> 缺陷 1 会让净值与 `duplicate_of_day` 的口径打架：同日重复被丢弃、跨日重复被加权。

## 四、账户定义：三个候选（需 owner 决策）

现口径的根问题是**没有「账户」**：组合 = 观点算术平均，N 即仓位，N 变化即杠杆变化。

### 方案 A：立场加权（改动最小）

- 分母改为「当期有盯市的**全部**观点数」，neutral 记 0 收益但占分母；
- 效果：同批数据 -5.71% → -0.86%，仓位从 100% 回到 ~30%；
- 代价：仍是「观点平均」，不是真实账户；历史净值需全量重算 + 切点登记。

### 方案 B：真账户净值（终局）

- 复用 `execution/portfolio.py`：100 万、单票 20%、总仓 80%、regime 系数；
- 净值直接取 `paper_equity`，与成交、费用、现金一致；
- 前提：**先有 long 信号**（当前 0）——否则净值恒为 1,000,000。

### 方案 C：双轨展示（可与 A 并行）

- 保留现曲线，改名「方向性观点等权指数」，明确它不是账户；
- 另加 long-only 子组合净值与现金基准，跑赢指数只在 long-only 上比；
- 代价：页面信息量上升，需要信息层级设计。

**建议**：先 C（改名 + 分解，零口径风险）→ 再 A（口径改造，需 delta + 全量重算）→ B 作为终局等买入信号恢复后落地。

## 五、落地顺序与门禁

1. **披露**（已落地）：`add-track-record-caliber-disclosure` — 不改任何数字。
2. **查买入信号**：为什么 10-08 之后 0 条 buy？是选股档位问题、还是 buy 被 1~3 天 supersede 吃掉？（建议先只读排查，不动 prompt）
3. **修缺陷 1**：同标的归并 —— 需 delta + `metrics.md` §1.12 追加口径 + derived 表重算。
4. **修缺陷 3**：superseded 补基准腿 —— 需确认 spec 语义。
5. **口径改造 A/C**：需 delta + 预登记 + 重算 + 页面标注切点版本。

**硬门禁**（沿用项目纪律）：

- 口径变更先改 `docs/evals/metrics.md` §1.12，再动代码；
- derived 表（`daily_marks`/`equity_curve`/`agent_metrics_daily`）重算前后读数不可混引；
- 重算后需在 `metrics.md` §2 时间线追加切点行；
- 交易日 17:55–20:45 与 15:30–17:10 不重建后端（本次改造涉及重启，须排窗口）。

## 六、不要做的三件事

1. **不要**为了让曲线「好看」而调整分母——A 方案的价值是让仓位可解释，不是让收益变正；
2. **不要**在没有 long 信号的情况下上线方案 B（会得到一条恒为 1,000,000 的直线，比现在更误导）；
3. **不要**用现有 5 笔 `superseded` 结算去调 prompt 或判定 agent 缺陷——样本 < 10，且全部是提前闭仓（AGENTS.md 红线「指标低 ≠ 能力差」）。
