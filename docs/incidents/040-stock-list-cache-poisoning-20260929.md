# 040: 股票列表缓存毒化——单次抓取失败清空进程内检索锚点，全股票「未找到」（2026-09-29）

## 症状

用户在深度模式查询「拓荆科技」，react agent 的 `search_stock('拓荆科技')` 与
`search_stock('688072')` 均返回「未找到匹配」，agent 最终答复「正式代码应为 688072，
但当前数据库未收录」——**误导性话术**：688072 拓荆科技在 AKShare 数据源中真实存在
（修复后实测宿主机与容器内均可命中，列表 5571 只、科创板 617 只）。

**发现渠道**：用户截图报告 → Langfuse trace 取证。

### Langfuse 证据（trace `9f17f5c5c8d705429bfea8c1e9d87658`，2026-09-29 12:32）

| 时间 | 调用 | 耗时 | 结果 |
|---|---|---|---|
| 12:32:10 | `search_stock('拓荆科技')` | **28.4s** | 未找到 |
| 12:32:40 | `search_stock('688072')` | **6.1s** | 未找到 |

两次调用均触发 Tavily web search（`search_api_call` span）——救援层走到了，但提取出的
688072 在 AKShare 验证环节被拒。**28.4s → 6.1s 的耗时坍缩是缓存毒化的直接证据**：
首次调用尝试了全量抓取（失败），第二次直接复用缓存的空列表、跳过抓取。

后端日志与 Langfuse 均无异常记录——异常被 `except Exception` 静默吞掉，零观测。

## 根因

`src/finance_agent/app_search.py` → `get_stock_list()`：

1. **失败结果被当成功缓存**：抓取异常时 `except Exception: _STOCK_LIST_CACHE = []`，
   空列表永久写入缓存；
2. **永不重试**：重入判断 `if _STOCK_LIST_CACHE is None` 对 `[]` 恒假——失败状态
   一直存活到进程重启；
3. **静默失败**：吞异常无日志，排查时后端日志与 trace 双双无迹（违反
   「排查 bug 必须同时查后端日志和 Langfuse trace」时才发现两边都没有可查的东西）。

**触发条件**：进程冷启动后首查。容器 12:32:07 启动，12:32:10 即收到查询——AKShare
全量列表抓取（18 分片下载）落在网络最不稳的窗口，抛异常。

### 连坐放大：四级降级收敛到同一锚点

`react_agent.search_stock_tool` 的四级降级（代码验证 → 名称匹配 → LLM 常识推理 →
Tavily web search → 模糊搜索）中，每一级候选都必须过 `_verify_stock_code` 对同一份
`get_stock_list()` 缓存做验证（信任锚点原则，防编造代码）。锚点为空时：

- LLM 常识推理答对 688072 → 验证失败 → 丢弃；
- Tavily 搜索答对 688072 → 验证失败 → 丢弃；
- 模糊搜索在空列表上 → 空。

锚点挂掉时降级链是**乘法失效**，不是加法备份。app_search 的唯一消费方就是
react_agent 搜索工具链，毒化窗口内全部检索请求（不限科创板）均「未找到」。

## 影响面

- react agent 的 `search_stock` 工具全量失效（任何股票），且失败话术误导用户
  「数据库未收录」；
- **不影响**深度分析管线的数据拉取（`fetch_kline`/quote 等有独立三级回退，见
  openspec specs/data-source-resilience）。

## 判定

**真问题（数据源缓存韧性缺陷，非模型/检索逻辑缺陷）**。LLM 推理与 web search 两层
都给出了正确答案，被验证层误杀。

## 修复（已实施）

`get_stock_list()` 失败语义重构：

1. **失败/可疑结果不缓存**：抓取异常，或列表低于 `_MIN_VALID_LIST_SIZE`（1000 只；
   完整 A 股 >5000，防半截列表毒化）时，返回空列表但缓存保持 `None`——下次调用自动重试；
2. **60s 失败冷却**：冷却期内直接返回空列表不重复打上游（避免上游故障期每次搜索
   都等 28s 抓取超时），冷却过后自愈；
3. **失败记 WARNING 带堆栈**：后端日志可查，不再静默。

复现测试：`tests/test_app_search.py::TestGetStockListResilience`（4 例，失败不缓存重试
自愈 / 异常小列表拒绝重抓 / 冷却期内不打上游且过期后恢复 / 失败告警日志）。

## 教训

1. **「失败」与「空」必须区分**：用 `None` 哨兵做「未加载」判断的缓存模块里，
   except 分支写 `[]` 等于把单次故障升格为进程生命周期内的长期状态。失败路径
   要么不写缓存，要么带 TTL；
2. **多级降级收敛到单一信任锚点时，锚点可用性必须独立保障**——否则降级链在锚点
   故障下全盲，且上层无法区分「锚点不可用」与「候选真不存在」（本次 agent 把
   两者混为一谈，产出了「未收录」的错误话术）；
3. 与 [008](008-deep-analysis-stuck-akshare-20260716.md) 同族（AKShare 拉取失败
   无重试）：008 在行情拉取层，本例在列表缓存层——AKShare 依赖的韧性缺口是
   家族性的，新增 AKShare 依赖时应默认带「失败不缓存 + 冷却重试 + 有声失败」三件套。
