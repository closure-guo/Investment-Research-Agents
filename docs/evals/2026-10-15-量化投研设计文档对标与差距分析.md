# 对标分析：个人量化投研设计文档 vs 本项目（2026-10-15）

**对标对象**：`基于LLM的个人量化投研设计文档.md`（v1.0，2026-10-13，外部设计稿：Qlib + RD-Agent + 四闸门 + 文本因子 + 防坑清单）
**本项目**：finance_analysis_agent（LangGraph 多 Agent 分析系统 + 自建选股/因子/执行/结算栈）
**一句话结论**：**数据与统计裁判这两条线，我们已经把文档主张的东西工程化落地得比它更细（部分闸门同值甚至更强）；真正的差距在「LLM 研发闭环」（一次性提案 vs 迭代研发）与三块数据地基（PIT 披露日 / 含退市股池 / 文本快照库）；而最大的分歧是哲学层——文档明令禁止的「LLM 预测 + 多 Agent 辩论下单」，正是本项目的核心决策层。**

---

## 1. 我们的量化分析管线（as-built）

| 层 | 我们的实现 |
|---|---|
| **数据面** | 全市场快照日批（15:30，新浪→东财回退；复权基准、停牌/退市行合成、时点截断防前视）→ `market_snapshot`（现 187 交易日 × 5.6k 票，含回填区）；逐票历史回填（raw/qfq 双口径，**无成交额列**）；证券主表 + 交易日历；单标的行情三级链（腾讯→东财→百度）；分析工具面（K 线/财务/宏观/新闻/舆情/同业） |
| **选股栈** | L1 确定性硬过滤（ST/上市天数/20 日流动性）→ L2 因子打分（DSL 因子库 → 截面 zscore → **IC 权重合成** → Top100 入榜）→ L3 LLM 排雷粗筛 → 精选池（keep ∩ **连续 3 日在榜**）→ 批量深度分析队列（并发 2） |
| **因子治理** | DSL（价量六字段）+ **闸 0–5**：结构查重 / 可计算性（缺失率 ≤20%）/ 单因子 **\|ICIR\|≥0.3** / 置换 999 + **BH-FDR q=0.1** / 池级增量（**\|IC 相关\|≤0.7** + 验证段 IR 增量）/ 样本外（**70/30 按日切分**）；因子库状态机（candidate/active/degraded/retired）+ IC 序列 + 事件史；衰减监控（60 日滚动 IC，连续 20 日负且 \|ICIR\|<0.1 → degraded）；LLM 提案月批（跨桶采样，同五道闸）；内置基线包注册日批（15:50，2026-10-15 新增） |
| **决策面** | 五层多 Agent（4 分析师并行 → Bull/Bear 辩论 → Trader → 风控辩论 → 基金经理批准）→ 观点落库（`predictions`，T+20 判定 + 价位触发位）→ cohort 固定宇宙夜批（10 票/夜） |
| **执行面** | 观点 → Signal 契约 → 组合目标（等权；单票 20%/总仓 80%）→ 确定性门禁（ST/停牌/一字板/T+1/整手/仓位上限）→ paper broker（**D+1 开盘口径撮合 + 滑点四档（按成交额分位）+ 佣金万 2.5(低 5 元) + 印花税千 0.5(卖出)**）→ 结算/盯市/净值曲线/战绩（**虚拟结算 vs 仿真成交 = 执行损耗**） |
| **回流与治理** | 决策记忆（情景→语义条款→注入）、judge 校准、完整性校验、13 个 ops 日批任务（调度/运行历史/手动补跑/单飞锁）、Langfuse 追踪 + eval 门禁 |

## 2. 逐项对照（按文档结构）

### 2.1 验证闸门（文档 G1–G4 vs 我们的闸 0–5）

| 文档闸门 | 我们 | 判定 |
|---|---|---|
| G1 IC/ICIR（Rank IC>0.03 且 ICIR>0.3） | 闸② \|ICIR\|≥0.3 且 \|IC 均值\|>0（**未要求均值>0.03**） | ✅ 同值（略宽） |
| G2 分层回测单调性（10 分位） | **无** | ❌ 缺 |
| G3 置换检验（p<0.05）+ 多重检验校正 | 闸③ 置换 999 + BH-FDR（显式 FDR 目标 q=0.1） | ✅ 更强 |
| G4 样本外 + 扣费回测 | 闸⑤ 样本外（70/30 切分、符号一致 + \|ICIR\| 达标）；**扣费不在因子闸**（在 paper broker） | ⚠️ 部分（口径不同：我们是「衰减+符号」而非「衰减<50%+扣费跑赢」） |
| 相关性去重 \|ρ\|>0.7 | 闸④ MAX_IC_CORRELATION=0.7 | ✅ 同值 |

### 2.2 LLM 的定位（最大的结构差异）

| 文档 | 我们 |
|---|---|
| **LLM 做研发，不做预测**；明令禁止「LLM 直接预测涨跌/选股」「多 Agent 辩论后下单」 | LLM 既做研发（因子提案月批）**又做预测**（五层多 Agent 决策）——决策层是本项目的主产品 |
| 因子研发 = RD-Agent 迭代闭环：读论文/研报 → 假设 → 编译表达式 → 回测 IC → **反馈迭代** + 知识库持久化复用 | 因子研发 = **一次性提案**（月批，跨桶采样 + 算子历史 IC 均值做弱反馈）→ 五道闸裁决 → 完。**无迭代循环、不读文献、无失败实验知识库回喂** |

### 2.3 数据地基

| 文档要求 | 我们 | 判定 |
|---|---|---|
| Qlib 二进制 + **PIT（时点真实性）** | 自建 SQLite 快照，**有「时点截断防前视」规格**（行情侧） | ⚠️ 路线不同（自建 vs 开源底座）；行情侧对齐 |
| 财务数据按**披露日**生效（非报告期） | 财报工具按**报告期**取数（图表标注明确「报告期截止日，非披露日」）——**无 PIT 对齐** | ❌ 缺 |
| 股票池**含历史退市股**（防幸存者偏差） | 池 = 当前上市（security_master 来自当日 spot）；历史时点池成分不可重建 | ❌ 缺（回测口径风险） |
| 文本快照库（**available_at** 时间戳，回测只读当时可见） | 文本用于**分析/决策**（有证据锚点/溯源治理），**无文本因子生成与回测** | ❌ 缺（差异化 alpha 线未开发） |

## 3. 我们领先的地方（文档空白区）

1. **决策质量治理**：价位交叉校验器、证据锚点追溯、基金经理批准门禁、决策记忆（条款注入）、滞回、结算/战绩闭环——文档对「LLM 输出的可信度工程」完全没有对应物（它用「禁止 LLM 预测」回避了这个问题）。
2. **工程纵深**：闸门是状态机 + 事件史 + IC 序列 + 幂等/单飞锁/运行历史/手动补跑的运维通道；文档的「自研闸门脚本（pandas+numpy）」是雏形形态。
3. **执行仿真精度**：滑点按成交额分位四档、一字板/停牌/T+1/整手门禁、虚拟结算对照——文档只有一行「扣费后比较」。
4. **观测与评估体系**：Langfuse trace、judge 校准、分桶归因纪律、E2E 门禁、指标台账——文档无。

## 4. 冲突点（需要拿数据裁决，而不是拿立场）

- 文档总纲与我们的核心架构正面冲突。**但我们已有的调研**（`docs/evals/2026-10-05-多Agent对单Agent选型调研.md`）结论：TradingAgents 原文**无单 agent 基线、无消融**；MAD（多 agent 辩论）常被自一致性追平（消方差不消偏差）；最强子命题 = 信息源分解 + 否决层。→ 决策层的增量价值**尚无双盲证据**；重测设计（P1 快照 + 自一致性对照臂）已备未立项。
- 现实画像佐证文档的怀疑：库内 172 条观点中 neutral 134 条（「全观望锁定」诊断），决策层在真实数据上极少给出可执行方向——若系统目标是「选出能买的股票」，当前决策层的增量价值存疑，而**统计裁判路线（选股栈 + 因子库）恰好是文档主张的方向**。
- 共存路径：两者并不互斥——决策层可定位为**研究与复盘工具**（其证据治理是资产），资金动作与收益归因走「统计裁判 + 纪律」。

## 5. 建议（分层，供裁决）

- **P0 接通已有资产**（今晚在做）：因子库冷启动——内置因子注册已接线；②= 准入面板深度 90→~170 + 补齐扩展回填 + 回填补「成交额」列 → `turnover_proxy` 可入库（深面板实测 \|ICIR\|=0.341）→ L2 解锁。
- **P1 对齐文档研发侧**：① 提案闭环加迭代反馈（拒收原因码已落摘要，回喂 prompt；建失败实验知识库）；② 补 G2 分层回测闸；③ 补 G4 扣费回测闸（复用 paper broker 的费用模型）。
- **P1 数据地基**：① 财务披露日 PIT（报告期→披露日，防前视）；② 回测用「含退市股」池重建；③ 文本 available_at 快照库（文本因子前置，差异化 alpha 的唯一未开发区）。
- **P2 战略裁决**：决策层消融实验（多 agent vs 单 agent vs 自一致性），用数据回答「辩论层值不值」；在此之前不建议扩大多 Agent 决策的算力投入。
- **明确不学**：整体迁移 Qlib——自建栈已有工程纵深与治理，迁移成本大于收益；只借其 PIT 语义与数据分层思想。
