## 4. 归因（不处置，incident 026 纪律）

本轮相对 r13 **不是单变量对比**，至少三处口径/环境变化叠加：

1. **trader prompt v33 → v34**：r13 运行时 Langfuse 的 trader 是未合并分支 `add-holdings-context` 的 v33（要求「受众持仓」上下文、缺省 sell_type=exit），而 main 代码不注入该上下文、缺省 short。本轮按 git 权威口径把 production 强制发布为 main 版 v34（incident 048）。→ 决策层材料与 dg/consistency 基线可能移动，跨 r13/r14 的这两维不可作单变量比较。
2. **数据链降级**：东财封禁 + AKShare 大面积连接失败，上游财务/行情回退路径生效，可能改变数字密度与可校验性（与 citation 指标放大方向一致）。
3. **报告长度/数字密度上升**：`citation_verifier_normalized` 与 `analyst_true_fail` 同步 ×3，更像「数字申报量增加」而非「分析师幻觉率上升」；须先按桶拆（数值/方向/归属/解析）再判定，禁止直接改 prompt。

已登记待归因桶（下一轮动作）：

- **citation 12/条 分桶**：从 9 条 deep 的 Langfuse trace 反解 FAIL 明细，按 `value_mismatch / direction_mismatch / coverage_gap / blocked(解析歧义)` 分桶，逐条人工终裁后再决定处置对象。
- **dg +0.85**：核对是否由 report 结构/证据引用变化造成（抽 3 条高分报告逐条对照 evidence_refs）。
- **relevance −0.44**：抽查 5 条 ≤4.667 的查询（尤其「茅台的现金流健康吗?」3.667），确认是查询焦点未逐条回应还是 rubric 判例漂移。
