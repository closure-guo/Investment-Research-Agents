# C2 · 白话档案：同一个「卖出」，四段代码翻译出了四个意思

**状态**：待做（第 1 批，最高优先）
**来源**：2026-11-21 架构评审侦察通道 2
**关联**：issue **#606**（open）· PR #595/#597（执行层消费侧，已合）· ADR-0018（predictions 表归属，不动）

## 一句话

每次分析产出三个价——**买入价、止损价、目标价**。但「卖出」这个词，系统里有 **4 个地方各自理解了一遍，理解得还不一样**。已经造成实际后果：战绩记分卡的方向和执行叙事相反（#606）。

## 现在长什么样

「卖出」有歧义：可以是**清仓离场**（价格按现价往下看），也可以是**做空**（价格逻辑整个反过来）。四段代码各按自己的理解翻译：

| 位置 | 它的理解 |
|---|---|
| `nodes/validate.py:44-50` | 卖出 → 一律当做空（不管 sell_type 是不是"清仓"） |
| `execution/signals.py:42-105` | 卖出 → 清仓（做空直接拒收） |
| `outcome/track_record/judgment.py:54-64` | 卖出 → 做空（清仓叙事被当做空，记分卡算反） |
| `outcome/settle.py:54-56` | 写死「只做多」（旧代码，谁也不调它，但留着） |

另外，一份决策从 LLM 文本到执行被**重新解释了 5 次**（validate 改一次 → 入库冻结时改一次 → 执行引擎再解析 JSON 一次 → 信号转换再映射一次 → 契约层正则回读叙事一次）。

## 已经造成的麻烦

- **#606（开着）**：记分卡方向反向、结算读数与执行叙事反向——不是维护累，是**算错了**。
- settle.py 旧路径哪天被误启用，写死的「只做多」立刻踩雷。
- openspec 里**没有任何条目定义「卖出/清仓场景下三个价的方向」**——这块行为现在是真空，各模块只能猜。

## 打算怎么修

立一个「总翻译」：`resolve_price_contract(决策) → 方向定好的三价`。

- 位置：放在校验（validate）与入库（ingest）之间——所有价格先经它定方向，下游（执行引擎、结算、记分卡）只读翻好的，不再各自理解。
- 吸收对象：validate 的方向强制逻辑、入库时的价格冻结、signals 里的价格清洗——三处合并成一个 owner。
- ADR-0018 的 predictions 表归属**不动**，总翻译在它上游。

## 好处（白话）

1. 「方向搞反」这类 bug 从根上绝迹——想理解错都没地方理解。
2. 单测穿过总翻译就能钉死方向矩阵，不用拉起整个模拟盘跑一遍才发现反了。
3. 顺手把 openspec 的契约真空填上——刚落地的 #595/#597 是消费侧的一半，补上 owner 侧就闭环了。

## 牵涉文件

`nodes/validate.py`、`outcome/track_record/ingest.py`、`execution/signals.py`、`execution/driver.py`、`outcome/settle.py`、`outcome/track_record/judgment.py`、openspec（新增 capability）。

- ADR-0018 已定的入库归属别顺手改——总翻译只在其上游。
- 执行引擎 #595/#597 刚落的消费逻辑别重复实现，契约层产出结构化值让它继续消费。
